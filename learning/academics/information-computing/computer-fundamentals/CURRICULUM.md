# 컴퓨터 원리와 활용 학습 설계서

## 1. 과정의 목표

이 과정은 초등 입문자가 컴퓨터 용어를 외우는 데서 끝나지 않고 다음 문장을 자신의 말로 설명할 수 있게 하는 것을 목표로 한다.

> 사람의 입력을 받은 하드웨어는 운영체제와 앱의 명령에 따라 데이터를 처리하고, 그 결과를 화면이나 소리로 보여 주거나 파일로 저장한다. 컴퓨터와 기기는 네트워크를 통해 다른 컴퓨터와 데이터를 주고받는다.

주차나 학기 길이에 맞춰 개념을 억지로 자르지 않는다. 학습자는 개념을 이해하고 확인 문제를 통과하면 다음 차시로 이동한다. 교사는 수업 시간에 따라 여러 차시를 묶거나 한 차시를 반복할 수 있다.

## 2. 설계 원칙

- 설명은 짧게 하고 관찰, 분류, 연결, 조작, 설명 활동을 중심으로 한다.
- 비유를 먼저 보여 준 뒤 반드시 실제 명칭과 정확한 역할을 연결한다.
- 하나의 개념을 이름, 역할, 다른 개념과의 관계까지 확인한다.
- 오답은 정답만 표시하지 않고 잘못 생각한 지점을 짧게 설명한 뒤 다시 풀게 한다.
- 모든 드래그 활동은 `선택하기 → 놓을 곳 선택하기` 방식으로도 수행할 수 있게 한다.
- Chromebook, iPad, PC에서 같은 학습 목표를 달성하되 기기별 조작 차이를 안내한다.
- 광고성 문구, 큰 장식 제목, 의미 없는 배너 없이 현재 학습 활동을 첫 화면에 둔다.
- 학습 활동은 실제 플레이 반복과 종료 조건이 있을 때만 게임이라 부른다. 그 외에는 탐구, 실습, 문제 풀이라고 표시한다.

## 3. 공통 차시 구조

1. **생각 열기**: 생활 속 장면이나 고장 상황을 한 장면으로 제시한다.
2. **원리 보기**: 어린이용 비유와 실제 개념을 나란히 설명한다.
3. **직접 해보기**: 분류, 연결, 설정, 순서 배치 또는 모의 조작을 한다.
4. **문제 풀기**: 개념 확인, 관계 이해, 상황 적용 문제를 푼다.
5. **오답 다시 보기**: 틀린 개념만 짧게 복습하고 다른 형태로 다시 푼다.
6. **내 말로 설명하기**: 한 문장 완성, 음성 또는 카드 배열로 원리를 설명한다.

### 공통 통과 기준

- 필수 문제의 80% 이상을 해결한다.
- 핵심 관계 문제를 적어도 한 번 맞힌다.
- 오답 문제는 피드백 후 다시 풀어 맞힌다.
- 마지막에 해당 개념을 한 문장으로 설명한다.

점수 대신 `연습 중`, `개념 이해`, `스스로 설명`의 세 상태를 사용한다.

## 4. 전체 개념 흐름

```text
컴퓨터와 디지털 기기
  → 입력·처리·저장·출력
  → 하드웨어와 소프트웨어
  → CPU·GPU·RAM·저장 장치
  → 운영체제와 앱
  → 바탕화면·홈 화면·창·설정
  → 드라이브·폴더·파일·확장자
  → 아이콘·원본·바로가기
  → 픽셀·해상도·색
  → 0과 1·bit·byte·용량
  → 문자·그림·소리·영상 데이터
  → 네트워크·인터넷·웹
  → 브라우저·검색·북마크·다운로드
  → 계정·보안·디지털 시민성
  → 알고리즘·코딩·문제 해결
```

### B. 컴퓨터 안의 하드웨어

공통 비유는 `컴퓨터는 하나의 학교`로 통일하되 비유가 실제 구조와 완전히 같지는 않음을 안내한다.

| 차시 | 학습 질문 | 핵심 개념과 비유 | 직접 해보기 | 문제와 통과 증거 |
|---|---|---|---|---|
| B01 | 본체 안에는 어떤 부품이 있을까? | CPU=명령을 처리하는 선생님, GPU=병렬로 계산하는 미술부원, RAM=작업 책상, 저장 장치=자료 사물함, 메인보드·전원·냉각 | 실제 본체 내부 그림을 관찰하고 부품을 계산·작업 공간·장기 보관·연결 지원 역할로 분류한다. | RAM 4GB/16GB와 저장 공간 256GB 사례처럼 새 상황에서 부품의 역할을 근거로 추리한다. |
| B02 | 컴퓨터 바깥에는 어떤 장치가 있을까? | 입력 장치, 출력 장치, 입출력 장치 | 키보드, 마우스, 터치 화면, 마이크, 카메라, 모니터, 스피커, 프린터를 분류한다. | 처음 보는 장치도 기능을 보고 분류한다. |
| B03 | 본체 안의 부품은 어디에 연결될까? | 메인보드=교실과 복도, 슬롯, 소켓, 회로 | 부품을 메인보드의 알맞은 위치에 놓는다. | 메인보드가 여러 부품을 연결한다는 점을 설명한다. |
| B04 | CPU는 왜 컴퓨터의 중심일까? | CPU=명령을 해석하고 계산하는 선생님, 코어, 클록 | 명령 카드를 순서대로 CPU에 보내 결과를 관찰한다. | CPU가 저장 창고가 아니라 처리 장치임을 구별한다. |
| B05 | GPU는 CPU와 무엇이 다를까? | GPU=많은 그림 조각을 동시에 처리하는 미술부원, 병렬 처리 | 한 명이 여러 일을 처리하는 경우와 여러 명이 같은 종류의 일을 나누는 경우를 비교한다. | CPU와 GPU에 적합한 작업을 구별한다. |
| B06 | RAM은 왜 작업 책상일까? | RAM=현재 자료를 펼치는 책상, 휘발성 메모리 | 앱을 열 때 책상에 카드가 쌓이는 모형을 조작한다. | RAM과 저장 장치의 차이, 전원을 끄면 사라지는 이유를 설명한다. |
| B07 | 캐시는 왜 CPU 가까이에 있을까? | 캐시=바로 꺼내 쓰는 필통, 작고 빠른 임시 공간 | 책장, 책상, 필통에서 같은 자료를 찾는 시간을 비교한다. | 캐시–RAM–저장 장치를 크기와 속도로 배열한다. |
| B08 | SSD와 HDD는 무엇을 보관할까? | 저장 장치=자료 사물함, 비휘발성 저장, SSD, HDD | 전원을 끈 뒤에도 남아야 할 데이터를 저장 장치에 옮긴다. | RAM 용량과 저장 용량을 혼동하지 않는다. |
| B09 | 전기와 열은 어떻게 관리할까? | 전원 공급 장치, 배터리, 방열판, 냉각팬 | 필요한 전력과 냉각 부품을 컴퓨터 모형에 연결한다. | 과열과 배터리 부족 상황의 원인을 구별한다. |
| B10 | 포트와 케이블은 왜 모양이 다를까? | USB-A, USB-C, HDMI, 오디오, 충전, 데이터 전송 | 용도에 맞는 포트와 케이블을 연결한다. | 억지로 꽂지 않고 모양과 기능을 먼저 확인해야 함을 설명한다. |
| B11 | 선이 없어도 어떻게 연결될까? | Wi-Fi, Bluetooth, NFC의 기초 | 키보드, 이어폰, 인터넷 연결에 알맞은 무선 방식을 고른다. | Bluetooth와 Wi-Fi의 대표 용도를 구별한다. |
| B12 | 컴퓨터가 느리면 어떤 부품을 살펴볼까? | 처리 속도, 작업 공간, 저장 공간, 네트워크 속도의 차이 | 느려짐 상황의 단서를 보고 CPU, RAM, 저장 공간, 인터넷 중 원인을 추리한다. | 관찰 근거 없이 느려짐 원인을 CPU로 단정하지 않는다. |

### D. 마우스·터치·키보드와 명령

### 출제 금지 기준

다음 유형은 정답률이 높아도 개념 이해를 측정하지 못하므로 출제하지 않는다.

- `무조건`, `항상`, `전부`, `절대로`, `~만` 같은 절대어가 정답 단서가 되는 OX 문항
- 상식적인 착한 행동이나 안전한 행동을 고르게 하는 유치원식 도덕 문항
- 설명 화면의 한 문장을 그대로 복사한 정의 암기 문항
- 틀린 선택지를 우스꽝스럽게 만들어 정답이 눈에 띄는 객관식 문항
- 하나의 단어만 보고도 풀 수 있고 원리나 관계를 생각할 필요가 없는 문항
- 운영체제의 특정 화면 모양만 외우게 하고 기능의 공통 원리를 묻지 않는 문항
- 함정 표현과 말장난으로 오답을 유도하는 문항

### 문항 작성 기준

- 관찰할 그림, 수치, 파일 구조, 화면 상태 또는 조작 결과를 먼저 제공한다.
- 학습자가 두 대상의 차이를 비교하거나 다음 결과를 예측하게 한다.
- 정답을 고른 뒤 `왜 그런가`를 관계 카드, 짧은 설명 또는 추가 조작으로 확인한다.
- 오답 선택지는 실제로 생길 수 있는 오개념에서 만들되 문장 길이와 표현 강도를 비슷하게 맞춘다.
- 같은 개념을 이름 맞히기, 적용, 원인 추론의 서로 다른 방식으로 확인한다.

### 수준에 맞는 대표 문제

1. **아날로그와 디지털**<br>
   교실 온도가 20.14°C에서 20.18°C로 변했다. 0.1°C 단위로 표시하는 디지털 온도계에는 두 순간이 모두 20.2°C로 나타났다. 실제 온도는 변했는데 표시가 같을 수 있는 까닭을 측정 단계와 연결해 설명한다.

2. **CPU·RAM·저장 장치**<br>
   두 컴퓨터의 저장 공간은 모두 256GB다. A는 RAM 4GB, B는 RAM 16GB이며 같은 앱 여러 개를 동시에 열었다. 어느 컴퓨터가 작업 공간을 더 넉넉하게 사용할 수 있는지 고르고, 저장 공간 256GB가 이 판단을 바꾸지 않는 이유를 설명한다.

3. **파일·바로가기**<br>
   `문서/과학/관찰.jpg`가 원본이고 바탕화면에는 그 파일의 바로가기가 있다. 바탕화면 항목을 지운 뒤 파일 탐색기의 `문서/과학` 폴더를 열었을 때 보일 결과를 예측하고, 원본과 연결 정보의 차이로 설명한다.

4. **해상도·화면 크기**<br>
   크기가 같은 두 화면에 각각 1024×768과 2048×1536 픽셀 격자를 표시한다. 같은 사진의 모서리가 어느 화면에서 더 세밀하게 표현될 수 있는지 픽셀 수를 근거로 판단한다.

5. **브라우저·검색 엔진**<br>
   iPad에서 Safari를 열어 Google 검색으로 학교 홈페이지를 찾았다. 이 과정에 등장한 앱, 검색 서비스, 웹사이트를 세 칸에 분류하고 각 단계가 다음 단계에 어떤 요청을 보냈는지 연결한다.

6. **Wi-Fi·인터넷**<br>
   태블릿은 교실 공유기에 연결되어 프린터로 문서를 보낼 수 있지만 외부 웹페이지는 열리지 않는다. 현재 가능한 연결과 끊긴 가능성이 있는 연결을 네트워크 그림에서 표시한다.

## 7. 시각 자료 제작 목록

모든 래스터 시각 자료는 원본을 별도로 보관하고 서비스용은 WebP로 변환한다. 이미지 안에 한글 명칭을 굽지 않고 HTML 텍스트와 대체 설명으로 표시한다.

### 공통 시리즈

- 컴퓨터 전체 구조와 입력–처리–저장–출력 흐름
- 데스크톱, 노트북, Chromebook, 태블릿, 스마트폰 비교
- 메인보드, CPU, GPU, RAM, SSD, HDD, 전원 공급 장치, 냉각 장치
- 학교 비유 장면: 선생님, 미술부원, 책상, 필통, 사물함, 복도, 전기실
- Windows형 바탕화면, Android형 홈 화면, iOS/iPadOS형 홈 화면, ChromeOS형 화면
- 파일, 폴더, 드라이브, 경로, 확장자, 원본, 바로가기 비교
- 마우스, 트랙패드, 터치, 키보드 조작 손동작
- 픽셀 확대, 해상도 비교, RGB 빛 혼합
- 8개 스위치와 bit/byte, KB–MB–GB–TB 크기 비교
- 문자, 그림, 소리, 영상이 숫자 데이터로 바뀌는 과정
- 기기–공유기–인터넷–서버 연결 흐름
- 브라우저, 검색 엔진, 웹사이트, URL, 탭, 북마크 비교
- 개인정보, 권한, 피싱, 안전한 다운로드 상황 카드
- 알고리즘, 반복, 조건, 이벤트, 디버깅 카드

### 이미지 기술 기준

- 대표 카드 이미지: 4:3 비율, 1024×768 기준
- 활동 장면: 16:9와 4:3에서 안전하게 잘리는 중앙 구도
- 투명 부품 그림: 투명 WebP
- 일반 장면: 손실 WebP, 눈에 띄는 글자·선 손상 없이 최적화
- `srcset`용 1배·2배 크기 제공
- 이미지마다 대상, 역할, 학습 목적이 드러나는 대체 텍스트 작성
- 실제 운영체제 화면은 상표를 복제한 스크린샷 대신 기능 중심의 단순화된 교육용 화면으로 제작
