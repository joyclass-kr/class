# 음악 이론 구조

음악 이론은 별도의 중간 페이지를 두지 않는다. 메인 `index.html`의 펼침 메뉴에서 각 앱으로 직접 이동한다.

```text
메인 인덱스
└─ 음악 이론
   ├─ 청음  → learning/arts/music-theory/ear-training/
   └─ 피아노 스케일·보이싱 → learning/arts/music-theory/piano-skills/
```

## 디렉터리 책임

- `ear-training/`: 음정·화음·음계·화음 진행·리듬·가락을 소리로 판별하는 훈련. 피아노 음원과 재생 엔진을 여기서 갖는다. 리듬은 악보를 보고 두드리기와 받아쓰기로 나뉘고, 받아쓰기는 8·16칸 정간보식 칸에서 시작해 셋잇단음표부터 악보 고르기로 넘어간다.
- `piano-skills/`: 스케일과 보이싱 연습

## 악보 고르기 보기 만드는 법

리듬 악보 고르기의 보기 넷은 **치는 자리 수가 모두 같아야** 한다. 수가 다르면 소리를 몇 번 들었는지
손가락으로 세기만 해도 답이 나온다. 그래서 보기는 정답에서 치는 자리 하나를 바로 옆으로 옮겨 만든다.
수가 그대로이고 악보도 한 군데만 달라 보이므로 어디서 치는지를 들어야 한다. 첫 박은 되도록 그대로
두어 시작을 견주지 못하게 한다.

## 악보 그리기

자리표(𝄞)와 임시표(♯ ♭ 𝄪)는 **직접 그리지 않는다.** 유니코드 글리프를 쓰되, 글꼴마다 글리프가 차지하는
자리와 크기가 달라 그냥 찍으면 오선에 맞지 않는다.

**SVG의 `getBBox()`로 재면 안 된다.** 그것은 글리프가 아니라 글꼴 줄상자를 돌려주어 ♭·♯·𝄞가 모두 같은
높이(줄 높이)로 나온다. 캔버스 `measureText()`의 `actualBoundingBoxAscent/Descent/Right`로 먹이 닿는
테두리를 재야 한다. 잰 값으로 크기를 맞추고(올림표 두 칸, 내림표 두 칸 반, 자리표 일곱 칸), 기준점을
음표 자리에 앉힌다. 자리표는 소용돌이(먹 높이의 63%)를 G선에 맞춘다. 캔버스와 SVG가 같은 글꼴을 써야
하므로 글꼴 이름은 `.sheet-glyph`의 계산된 값을 읽어 쓴다. 손으로 길(path)을 그리려 들면 지렁이가 된다.
온음표만은 글리프가 아니라 타원 둘 + evenodd로 그린다(가운데 구멍이 비스듬히 뚫린 고리).

조표는 개수만 늘어놓으면 뜻이 없다. 임시표가 어느 줄과 칸에 붙는지가 조표이므로, 오선·자리표를 함께
두고 통째로 줄여서 작게 놓는다(원판 가운데 `SIG_SCALE`).

오선 길이는 칸 수가 적어도 같게 둔다(`minWidth`). 짧은 오선이 넓은 자리에 떠 보이면 망가져 보인다.

오도권 원판 가운데에는 오선을 그리지 않는다. 올림표·내림표만 작게 모아 몇 개인지 보이면 된다.
같은 소리를 다른 이름으로 적는 조는 세 자리(B=C♭, F♯=G♭, D♭=C♯)뿐이므로 그 칸에만 작은 글씨로
`= C♭`처럼 덧붙이고, 새 단추나 새 자리는 만들지 않는다.

보기 악보는 차시가 달라도 같은 크기여야 한다. 폭을 `viewBox` 눈금 × 배율로 못 박고(`EXAMPLE_ZOOM`),
칸 너비에 맞춰 늘이지 않는다. 위아래 여백은 음표가 닿는 데까지만 남긴다.

## 설명 차시는 한 화면

크롬북 1366×768, 아이패드 1024×768·1180×820·768×1024에서 제목·글·건반·단추가 늘 보이고 바닥이
밀리지 않아야 한다. 그 크기에 들어가는 보기는 한 차시에 셋까지다. 넷 이상이면 차시를 나눈다
(3화음 → 장·단 / 감·증, 교회 선법 → 장음계 쪽 / 단음계 쪽).

## 청음 첫 화면

첫 화면에는 음정·화음·음계·리듬 네 갈래와 찾아보기만 둔다. 갈래를 누르면 그 갈래의 과정 하나와
혼자 연습만 있는 화면으로 들어간다. 한 화면에 열네 개를 늘어놓으면 1366×768에서 481px가 넘쳐
음계와 리듬이 화면 밖으로 밀려나므로 갈래를 나눈다.

가락 받아쓰기는 음정 갈래에, 오도권 원판은 찾아보기에 둔다. 갈래 화면에는 갈래 이름을 다시 적지
않으므로, 연습 이름 자체에 갈래가 드러나야 한다(`Interval Listening(음정 듣기)`).

## 공통 설계 원칙

- 앱끼리 진도와 학습 기록을 섞지 않는다.
- 별도의 추천 또는 이어하기 화면을 만들지 않는다.
- 강제로 잠그는 단계를 두지 않는다.
- 제목 아래 곁말, 머리 이름표, 권유 문구를 넣지 않는다. 화면에 있는 말은 모두 문제를 푸는 데 쓰이는 말이어야 한다.
- 학생용 주요 조작은 44×44 CSS 픽셀 이상으로 만든다.
- 1024×768과 1180×820 가로 화면을 먼저 설계하고 768×1024 세로 화면과 좁은 세로 화면을 함께 지원한다.

  stats: { interval: { P5: { right: 0, total: 0 } } },
  setup: { interval: { level: "easy", mode: "harmony", items: [] } }
