# 실용화성학 역량 지도

이 문서는 단원 수나 차시 수를 정하기 위한 목차가 아니다. 학생이 실제 음악 상황에서 수행해야 하는 능력, 그 능력의 선행관계, 수행을 입증할 과제, 필요한 시청각 자료를 먼저 정의한다. 화면의 학습 과제 수와 묶음은 이 지도를 구현하는 과정에서 결정한다.

## 최종 수행

학생은 짧은 리드시트를 보고 다음 일을 할 수 있어야 한다.

- 코드 기호를 해석해 건반에서 연주한다.
- 멜로디와 조성에 맞는 코드를 선택한다.
- 전위와 보이싱으로 자연스럽게 연결한다.
- 진행을 다른 조로 옮긴다.
- 필요할 때 7화음, 세컨더리 도미넌트, 차용화음을 사용한다.
- 자신이 선택한 화성을 악보, 코드 기호, 로마숫자, 소리로 설명한다.

## 과정의 비목표

- 전통 화성학 교재의 장 순서를 축약해 재현하지 않는다.
- 용어 정의를 기억하는 것만으로 완료 처리하지 않는다.
- C 장조 한 가지 예를 맞힌 결과를 전이 가능한 실력으로 보지 않는다.
- 모든 내용을 같은 분량, 같은 문제 수, 같은 화면 형식에 맞추지 않는다.
- 직접 연주·구성·비교가 없는 활동을 게임이라고 부르지 않는다.

## 학습 과제를 나누는 기준

학습 과제는 아래 조건을 모두 만족할 때 독립된 경계가 된다.

1. 학생이 끝에서 보여 줄 수 있는 하나의 관찰 가능한 수행이 있다.
2. 그 수행에만 해당하는 대표 오개념이나 실패 형태가 있다.
3. 다른 수행과 구별되는 조작 또는 피드백이 필요하다.
4. 앞에서 배운 능력을 새로운 조·음역·진행에 전이해 확인할 수 있다.

같은 조작과 같은 성공 기준을 사용하는 개념은 합친다. 서로 다른 산출물이나 피드백 엔진이 필요한 수행은 분리한다. 따라서 화면 수는 미리 정하지 않는다.

## 역량 노드

노드 ID는 순번이 아니라 의미를 나타낸다. 청음은 별도 부록이 아니라 모든 노드의 수행 증거에 포함한다.

| 역량 ID | 학생이 실제로 하는 일 | 선행 역량 | 필수 시각 자료 | 필수 청각·조작 자료 | 완료를 입증하는 수행 |
|---|---|---|---|---|---|
| `SYMBOL_READ` | C, Cm, C7, Cmaj7, Csus4, Cadd9의 기호를 구성음 지시로 해석한다. | 건반의 음이름 | 코드 기호를 근음·3음·5음·7음·부가음으로 분해한 도식 | 같은 근음의 코드 기호별 A/B 청음 | 처음 보는 코드 기호를 구성음과 역할로 풀어 말한다. |
| `TRIAD_BUILD` | 임의의 근음에서 장·단·감·증3화음을 만든다. | `SYMBOL_READ`의 근음 읽기 | 실제 오선보와 건반의 반음 거리 | 건반에 음을 직접 선택하고 블록·아르페지오로 재생 | C가 아닌 여러 근음에서 철자를 지켜 화음을 구성한다. |
| `QUALITY_HEAR` | 장·단·감·증3화음을 소리와 간격 근거로 판별한다. | `TRIAD_BUILD` | 네 화음의 3음·5음 변화 비교 악보 | 같은 근음·음역·세기의 통제된 비교 청음 | 감정 형용사만 쓰지 않고 간격 또는 변화음을 근거로 판별한다. |
| `SLASH_BASS` | 전위와 슬래시 코드를 베이스 선율로 사용한다. | `TRIAD_BUILD` | 기본위치·전위 악보와 베이스 강조 | 같은 코드의 세 베이스 배치 비교, 정확한 음역 건반 구성 | 코드 정체를 유지하면서 지정된 베이스로 배치한다. |
| `VOICE_LEAD` | 공통음을 유지하고 각 성부 이동을 줄여 코드를 연결한다. | `SLASH_BASS`, `TRIAD_BUILD` | 성부별 이동선과 두 보이싱 비교 악보 | 거친 연결과 최소 이동 연결 A/B, 음별 솔로 듣기 | 같은 진행을 두 방식으로 배치하고 더 적절한 쪽의 이유를 설명한다. |
| `KEY_MAP` | 장조·단조의 조표와 음계를 실제 코드 재료로 사용한다. | 음이름과 반음 이동 | 오도권 암기표보다 건반·조표·음계 대응도 | 으뜸음과 이끎음, 장·단조 음계 비교 | 주어진 조의 음을 악보와 건반에서 정확히 선택한다. |
| `DIATONIC_BUILD` | 한 조의 각 음 위에 다이어토닉 코드를 만든다. | `TRIAD_BUILD`, `KEY_MAP` | 음계 위에 3도씩 쌓이는 악보와 로마숫자 지도 | 한 조의 일곱 코드 연속 듣기와 직접 구성 | 여러 조에서 지정된 로마숫자 코드를 만든다. |
| `FUNCTION_HEAR` | 토닉·프리도미넌트·도미넌트를 역할로 듣고 분류한다. | `DIATONIC_BUILD` | 기능 흐름과 실제 코드 후보 지도 | 같은 코드가 다른 문맥에서 맡는 역할 비교 | 코드 이름이 아니라 앞뒤 문맥을 근거로 기능을 설명한다. |
| `CADENCE_SHAPE` | 정격·변격·반·위장종지의 끝맺음을 구별하고 만든다. | `FUNCTION_HEAR`, `VOICE_LEAD` | 마지막 두 화음과 외성 진행 악보 | 같은 멜로디에 다른 종지를 붙인 비교 청음 | 원하는 완결감에 맞는 종지를 선택하고 외성 진행을 완성한다. |
| `PROGRESSION_PLAY` | I–V–vi–IV, vi–IV–I–V 등 반복 진행을 자연스럽게 반주한다. | `FUNCTION_HEAR`, `VOICE_LEAD` | 리드시트 마디와 보이싱 경로 | 메트로놈·블록·분산 반주, 실시간 건반 연주 | 루프를 끊지 않고 여러 보이싱으로 연주한다. |
| `SEVENTH_BUILD` | maj7, m7, 7, m7♭5, dim7을 구성하고 구별한다. | `TRIAD_BUILD`, `DIATONIC_BUILD` | 3화음에 7음이 추가되는 악보 | 같은 근음의 7음 종류 비교 청음과 직접 구성 | 코드 기호를 보고 7음까지 정확한 철자로 만든다. |
| `GUIDE_TONE` | 7화음의 3음과 7음을 다음 화음으로 연결한다. | `SEVENTH_BUILD`, `VOICE_LEAD` | 가이드톤 두 성부만 강조한 악보 | 전체 화음과 가이드톤만 따로 듣기 | ii–V–I에서 3음·7음의 해결 방향을 연주하고 설명한다. |
| `COLOR_CHORD` | sus2, sus4, add9, 6, 9, 11, 13의 표기와 사용 맥락을 구별한다. | `SYMBOL_READ`, `SEVENTH_BUILD` | 3음의 대체와 부가, 텐션 적층 비교 | 같은 근음에서 원형과 색채화음 비교 | 표기에 맞는 구성음을 만들고 멜로디와 충돌하는 텐션을 수정한다. |
| `TRANSPOSE` | 코드·멜로디·베이스를 관계를 유지한 채 다른 조로 옮긴다. | `KEY_MAP`, `DIATONIC_BUILD`, `PROGRESSION_PLAY` | 원조와 이조의 로마숫자·악보 병렬 비교 | 전후 조의 동일 진행 비교, 목표 조 건반 연주 | 익숙하지 않은 조에서도 진행 전체를 옮겨 연주한다. |
| `HARMONIC_RHYTHM` | 코드가 바뀌어야 할 시점과 유지할 시점을 정한다. | `PROGRESSION_PLAY`, `CADENCE_SHAPE` | 강박·약박·긴 음·구절 경계 표시 악보 | 같은 멜로디의 느린·빠른 화성 리듬 비교 | 모든 멜로디 음마다 코드를 바꾸지 않고 구조적 변화 지점을 선택한다. |
| `MELODY_HARMONIZE` | 멜로디 음의 코드톤 역할과 기능 흐름을 고려해 화성화한다. | `HARMONIC_RHYTHM`, `FUNCTION_HEAR`, `VOICE_LEAD` | 멜로디·후보 코드·베이스의 세 층 비교 | 멜로디만, 후보별 화성, 완성 반주의 순차 비교 | 하나의 정답을 고르는 대신 둘 이상의 안을 만들고 선택 근거를 설명한다. |
| `SECONDARY_DOMINANT` | 목표 코드의 V7을 만들어 일시적으로 강조한다. | `SEVENTH_BUILD`, `FUNCTION_HEAR`, `GUIDE_TONE` | 변화음과 목표음의 반음 해결 표시 | 다이어토닉 진행과 세컨더리 도미넌트 적용 진행 A/B | 목표 코드를 먼저 정하고 V/x를 구성·해결한다. |
| `BORROWED_CHORD` | 병행조의 화음을 차용해 색채를 바꾸고 원조로 돌아온다. | `KEY_MAP`, `FUNCTION_HEAR`, `VOICE_LEAD` | 원조·병행조 음계와 공통/변화음 비교 | IV–iv–I, ♭VII–IV–I 등의 비교 청음 | 차용된 음을 찾고 기능·성부 진행을 설명한다. |
| `LEAD_SHEET_PROJECT` | 짧은 리드시트를 분석·이조·보이싱·화성화해 완주한다. | 필요한 앞선 역량들의 조합 | 실제 길이의 리드시트, 보이싱 메모, 로마숫자 분석층 | 멜로디·베이스·반주 개별/전체 재생과 녹음 비교 | 정답 선택이 아니라 완성된 연주·편곡 결과와 선택 근거를 제출한다. |

## 선행관계

```text
SYMBOL_READ → TRIAD_BUILD → SLASH_BASS → VOICE_LEAD
                  └──────→ QUALITY_HEAR

KEY_MAP + TRIAD_BUILD → DIATONIC_BUILD → FUNCTION_HEAR
                                            ├→ CADENCE_SHAPE
                                            └→ PROGRESSION_PLAY

TRIAD_BUILD → SEVENTH_BUILD → GUIDE_TONE
                     └──────→ COLOR_CHORD

PROGRESSION_PLAY + KEY_MAP → TRANSPOSE
PROGRESSION_PLAY + CADENCE_SHAPE → HARMONIC_RHYTHM → MELODY_HARMONIZE
FUNCTION_HEAR + SEVENTH_BUILD + GUIDE_TONE → SECONDARY_DOMINANT
FUNCTION_HEAR + KEY_MAP + VOICE_LEAD → BORROWED_CHORD

필요한 역량들의 조합 → LEAD_SHEET_PROJECT
```

이 그래프는 단일 직선 진도를 강제하지 않는다. 예를 들어 건반 경험이 있는 학생은 `SYMBOL_READ` 진단을 통과하고 `TRIAD_BUILD`부터 시작할 수 있다. 모든 역량은 열어 두되 현재 수행 결과에 따라 다음 과제를 추천한다.

## 기존 10차시 시안에 대한 판정

폐기한 초기 시안은 아래와 같이 서로 다른 수행을 한 화면에 함께 넣었다. 이 결합은 설명 분량이 아니라 수행 증거가 다르기 때문에 분리 대상이다.

| 현재 구현 | 판정 | 이유 |
|---|---|---|
| 코드 기호를 소리로 바꾸기 | 분리 | `SYMBOL_READ`와 `TRIAD_BUILD`는 입력과 성공 기준이 다르다. |
| 장·단·감·증3화음 구별하기 | 분리 또는 진단 분기 | 직접 구성과 청음 판별은 서로 다른 오류 피드백이 필요하다. |
| 전위와 베이스음 | 유지 가능 | `SLASH_BASS`라는 하나의 수행으로 묶인다. |
| 최소 움직임 보이싱 연결하기 | 유지 가능 | `VOICE_LEAD`라는 하나의 수행으로 묶인다. |
| 다이어토닉 코드 지도 | 분리 | `KEY_MAP`, `DIATONIC_BUILD`, `TRANSPOSE`가 섞여 있다. |
| 화음의 기능과 종지 | 분리 | 기능 분류, 가이드톤 해결, 종지 구성은 산출물이 다르다. |
| 자주 쓰는 진행을 여러 조로 연주하기 | 분리 | 반복 진행 연주, ii–V–I 가이드톤, 조옮김이 섞여 있다. |
| 7화음과 코드의 색채 | 분리 | 7화음 구성과 기능적 해결은 다른 수행이다. |
| 멜로디에 코드 붙이기 | 분리 | 화성 리듬 결정과 코드 후보 선택·보이싱이 섞여 있다. |
| 조옮김과 세컨더리 도미넌트 | 반드시 분리 | 다이어토닉 전이와 비다이어토닉 기능화음은 선행관계부터 다르다. |

초기 시안에 없었던 `COLOR_CHORD`, `BORROWED_CHORD`, `LEAD_SHEET_PROJECT`도 현재 역량 지도에 포함한다. 반대로 실제 학생 수행에 기여하지 않는 용어 설명은 독립 화면으로 만들지 않고 필요한 역량 안에서 제공한다.

## 화면과 평가 원칙

- 첫 화면은 총 차시 수를 강조하지 않고 현재 추천 수행과 역량 지도를 먼저 보여 준다.
- 각 역량은 `설명 → 악보/건반 비교 → A/B 청음 → 직접 조작 → 다른 조·음역에 전이`의 증거 사슬을 가진다.
- 문제 수를 모든 역량에 동일하게 고정하지 않는다. 오개념과 전이 범위를 덮을 만큼만 서로 다른 문제를 제공한다.
- 완료는 용어 선택 점수가 아니라 해당 역량의 실제 구성·연주·분석 성공으로 판정한다.
- 청각 문제는 음량·음역·보이싱을 통제하여 비교 대상 외의 단서로 맞히지 못하게 한다.
- 악보 문제는 철자가 답을 결정할 때 반드시 표기를 제공하고, 소리만으로 증4도와 감5도 같은 답을 요구하지 않는다.
- 모든 학생 조작은 44×44 CSS 픽셀 이상이며 1024×768, 1180×820, 768×1024에서 핵심 과제가 먼저 보인다.
