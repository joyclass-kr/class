# 메타인지 진단

학생이 스스로 매긴 확신과 실제 정답 여부를 대조해, "아는 것"과 "안다고 느끼는 것"의
간격을 수치로 보여 주고 규칙 기반 상담 리포트를 돌려준다.

자기보고 설문(MAI 계열)을 쓰지 않는다. 설문 점수는 실제 수행과 잘 맞지 않기 때문에,
문항마다 확신도를 받아 캘리브레이션을 직접 재는 방식을 택했다.

## 파일

| 파일 | 하는 일 |
|---|---|
| `items.js` | 기본(학년 무관) 진단 문항 24개 + 확신도 척도. `kind` 태그(plain/trap/looksHard)가 진단의 핵심이다. |
| `items-grade3.js` ~ `items-grade9.js` | 학년별 문항 세트(초3~중3, 각 16문항). 아래 "학년별 세트" 참고. |
| `metrics.js` | 지표 산출·유형 분류·상담 카드 생성. 브라우저와 Node 양쪽에서 동작한다. |
| `app.js` | 화면 흐름, SVG 차트, 서버 저장. 어떤 문항 세트를 쓰든 그대로 재사용된다. |
| `index.html` | 기본 진단 화면 + 학년 고르기 링크. `styles.css`는 포털 디자인 토큰을 그대로 쓴다. |
| `grade3.html` ~ `grade9.html` | 학년별 진단 화면. `index.html`과 구조는 같고 불러오는 문항 세트만 다르다. |
| `test-metrics.js` | 지표 엔진 + 기본 문항 세트 검증. `node test-metrics.js` |
| `test-grade3-items.js` ~ `test-grade9-items.js` | 학년별 문항 세트 검증(같은 규칙을 세트별로 적용). `node test-gradeN-items.js` |
| `verify-shuffle.js` | 선택지 섞기 실주행 검증(Playwright). `node verify-shuffle.js` |
| `verify-export.js` | 내려받는 결과 파일 검증(Playwright). `node verify-export.js` |

서버 쪽은 `game-hub-server/metacognition.js`,
`game-hub-server/migrations/004-metacognition.sql`에 있다.

## 학년별 세트

`items.js`(24문항, 초5~중1 대상 고정 세트)와 별개로, 초3~중3 각 학년에 맞춘
16문항 세트가 학년마다 따로 있다. 설계 원칙:

- **레벨 이름은 "그 학년이 끝났다"는 보장이 아니라 "그 이전 학년까지는 확실히
  끝났다"는 보장이다.** 예를 들어 "초5 레벨"은 초5 3월에 봐도 초5 12월에 봐도
  똑같이 풀 수 있어야 하므로, 초5 내용이 아니라 **초4까지** 배운 내용만 쓴다.
  실제 매핑은 `items-gradeN.js` 파일 상단 주석에 학년별로 적어 두었다.
- 과학은 초1~2에 정식 교과서 실험 단원이 없어서, 초3 레벨의 과학 문항은
  교과 지식이 아니라 학교에서 안 배워도 알 수 있는 일상 관찰 사실로 채웠다.
- 함정(trap) 문항 중 직관적 오류(도박사의 오류, 조건문 역전 오류, 상관·인과
  혼동 등)에 기대는 것은 지식이 아니라 사고 습관을 재는 것이라 학년을 걸쳐
  재사용해도 된다. 다만 답이 분수·퍼센트 같은 표기를 쓰면 그 표기를 배운
  학년 이후로만 재사용해야 한다(같은 함정이라도 표현 방식이 학년을 탄다).
- 문항 배치 원칙(정답 위치 분포, 선택지 길이로 못 찍게 막기)은 기본 세트와
  동일하고, `test-gradeN-items.js`가 세트별로 검사한다. 새 학년을 추가하거나
  문항을 고치면 해당 검사를 반드시 다시 돌릴 것.
- `grade{N}.html`은 `items.js` 대신 `items-gradeN.js`만 불러오고, `app.js`를
  불러오기 전에 `window.METACOG_ITEM_SET_VERSION`과 `window.METACOG_LEVEL_KEY`를
  지정해 둔다. `app.js`는 이 값이 있으면 그 값을, 없으면(`index.html`) 기존
  기본값을 그대로 쓴다 — 진행 상황 저장 키(`localStorage`)도 학년별로 따로
  갈라지므로 서로 다른 학년 페이지를 오가도 진행 중인 답이 섞이지 않는다.
- 서버(`metacognition.js`)는 `ITEM_SET_REGISTRY`에 `itemSetVersion` 문자열로
  각 세트를 등록해 두고, 제출된 `itemSetVersion`으로 세트를 찾아 그 세트
  기준으로 채점·저장한다. 등록되지 않은 버전 문자열은 `UNKNOWN_ITEM_SET`으로
  거부한다 — 클라이언트가 임의의 문항·정답 세트를 서버에 강요할 수 없다.

## 지표

| 이름 | 산출식 | 읽는 법 |
|---|---|---|
| 정답률 | 맞은 문항 / 전체 | 이 진단은 함정 문항 비중이 높아 보통 시험보다 낮게 나온다 |
| 평균 확신 | 확신도 평균 (0~1) | |
| **과신 정도 (bias)** | 평균 확신 − 정답률 | +0.10 넘으면 과신, −0.10 아래면 과소평가 |
| **변별도 (discrimination)** | 정답 문항 평균 확신 − 오답 문항 평균 확신 | 0.15 이상이면 자기 점검이 작동. 0에 가까우면 알고 모름을 못 가린다 |
| 캘리브레이션 오차 (ECE) | 구간별 \|확신 − 실제 정답률\|의 문항 수 가중 평균 | 0에 가까울수록 좋음 |
| Brier | (확신 − 정오)²의 평균 | 정확도와 조율을 함께 반영 |
| 함정 대비 (trapPenalty) | 함정 문항 bias − 평범 문항 bias | 0.15 넘으면 직관에 제동이 안 걸린다는 뜻 |

`bias`와 `discrimination` 두 축으로 6개 유형을 나누고, 유형별 2주 실행 계획을 붙인다.

## 몰라도 맞히는 요령 막기

요령으로 맞힌 정답이 섞이면 정답률이 부풀고, 그만큼 과신 지표(bias = 평균 확신 −
정답률)가 실제보다 작게 나온다. 이 진단에서는 지표를 통째로 무너뜨리는 문제다.

v1에는 실제로 두 개의 구멍이 있었다. 정답이 2번인 문항이 24개 중 23개였고,
정답이 가장 긴 선택지인 문항이 9개(38%)였다. 지금은 세 겹으로 막는다.

1. **정답 위치를 네 자리에 6개씩** 배치한다.
2. **한 문항 안에서 선택지 길이를 비슷하게** 맞춘다. 긴 선택지를 짧은 오답과 섞어
   두면 "길어 보이는 것"이 단서가 된다. 오답도 정답만큼 자세히 쓴다.
3. **`app.js`가 학생마다 선택지 순서를 섞는다.** 답은 원래 번호로 되돌려 보내므로
   서버 코드는 이 섞기를 몰라도 된다. 이어서 풀 때는 저장된 순서를 그대로 쓴다.

`test-metrics.js`가 1·2를 매번 검사한다 — 정답 위치 분포, 무조건 n번 찍기,
가장 긴/짧은 선택지 찍기가 모두 우연(33%) 아래여야 통과한다.
`verify-shuffle.js`는 브라우저를 실제로 띄워 3을 검사한다. 화면 글자만 보고 정답을
고르면 100%, 오답만 고르면 0%가 나오는지 확인해 번호 되돌리기가 맞는지 본다.

**문항을 고치면 두 스크립트를 반드시 다시 돌릴 것.** 사람이 문항을 쓰면 정답을
비슷한 자리에 놓고 정답만 길게 쓰는 버릇이 거의 반드시 다시 나온다.

## 설계상 지켜야 하는 것

1. **진행 중에 정오를 알려 주지 않는다.** 중간 피드백이 들어가면 이후 문항의 확신도가
   오염되어 캘리브레이션이 성립하지 않는다.
2. **서버는 클라이언트가 보낸 요약 수치를 저장하지 않는다.** `metacognition.js`가
   응답 원자료로부터 지표를 다시 계산해 넣는다. 화면 코드가 바뀌거나 값이 조작돼도
   저장된 지표는 문항 세트와 산출식에만 의존한다. 클라이언트가 보낸 요약은
   `client_summary` 칸에 원문 그대로만 남겨 두어, 두 값이 어긋나면 추적할 수 있게 했다.
3. **문항을 교체할 때 `plain`은 6개 이상 유지한다.** `trapPenalty`의 기준선이 흔들린다.
4. **`items.js`를 고치면 `itemSetVersion`을 올린다.** 문항이 달라지면 이전 기록과
   같은 척도로 비교할 수 없다. DB의 `item_set_version` 칸으로 갈라서 본다.

## API

모두 `/api/metacognition` 아래에 있고, 기존 학생·교사 세션 인증을 그대로 쓴다.

| 메서드 | 경로 | 권한 | 설명 |
|---|---|---|---|
| POST | `/attempts` | 학생 | 결과 제출. 절반 미만만 풀면 거부한다. |
| GET | `/attempts/mine` | 로그인 | 본인 기록 최근 20건 |
| GET | `/teacher/class-summary` | 교사 | 학급 요약. 과신이 큰 학생이 위로 온다 |
| GET | `/teacher/export.csv` | 교사 | 연구용 내보내기. 이름·학번은 포함하지 않는다 |

서버에 연결되지 않은 상태(파일로 직접 열기, 비로그인)에서도 진단과 리포트는 그대로
동작하고, 결과는 브라우저에만 저장된다.

## 결과 내려받기

두 가지를 준다. 학생·학부모용과 분석용은 필요한 게 다르기 때문이다.

- **결과 리포트 (.html)** — 화면의 리포트를 그대로 복사해 담은 파일 한 장. 열면 본
  것과 같은 내용이 나오고, 브라우저에서 인쇄하면 A4 몇 장으로 뽑힌다. 원자료도
  `<script type="application/json" id="metacog-raw">` 블록에 함께 들어 있어, 파일
  하나만 챙기면 읽는 것과 분석하는 것이 둘 다 된다.
- **응답 원자료 (.json)** — 문항별 응답과 요약 수치만 담은 파일.

주의할 점 두 가지:

1. **파일 이름은 반드시 아스키로 짓는다.** 한글이 하나라도 들어가면 크로미움이
   `download` 속성의 이름을 통째로 버리고 확장자 없는 `download`로 저장한다.
   확장자가 없으면 학생이 파일을 열지 못한다.
2. **인쇄 스타일을 같이 손봐야 한다.** 화면이 어두운 바탕에 밝은 글씨라 그대로
   인쇄하면 흰 종이에 흰 글씨가 된다. `app.js`의 `PRINT_CSS`가 `:root` 변수를
   밝은 배경용으로 다시 정의해 뒤집고, 색을 속성으로 직접 갖고 있는 SVG는 따로
   덮는다. `verify-export.js`가 인쇄 모드에서 밝은 글씨가 남았는지 매번 검사한다.

## 남은 일

- 교사 화면: `/teacher/class-summary`를 쓰는 학급 대시보드가 아직 없다. API만 있다.
- 재검사 비교: 같은 학생의 1차·2차 결과를 나란히 보여 주는 화면.
- 문항 난도 검증: 실제 학급 데이터로 문항별 정답률을 확인한 뒤 지나치게 쉬운/어려운
  문항을 교체할 것.
